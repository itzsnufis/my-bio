stack

Levels, not percentages.

Nobody is 87% proficient at a language, and nobody has ever been helped by a progress bar shaped like a skill. So this page lists what I actually reach for, how often, and where the sharp edges are — core first, then low-level, then everything that holds the two together.

  • rule no percentages
  • levels daily · often · occasional
  • this site HTML + SCSS
  • daily — open in an editor most days
  • often — reached for regularly, not every day
  • occasional — used when the problem asks for it

Core & low-level

Where most of the code lives.

Core

the working set

  • C++ daily Systems and tooling. The language I think in when memory layout is the actual problem.
  • Python daily Automation, analysis, throwaway experiments. Prototype first, rewrite only if it earns it.
  • Go often Services and CLI tools. One binary, few dependencies, builds in the time it takes to sip coffee.
  • Java occasional The ecosystem still pulls its weight on some jobs. Verbose, but predictable.

Low-level & hardware

close enough to touch

  • C daily Kernels, drivers, glue. Small surface, long lifetime, no opinions about my mistakes.
  • Zig often New low-level code, especially the kind where C would happily let me shoot a foot off.
  • Rust often Where ownership rules save a class of evenings that would otherwise go to memory bugs.
  • Assembly (x86-64) occasional Boot paths, interrupt stubs, and the spots where the compiler needs supervision.
  • Electronics · I2C, SPI, level shifting often Datasheets, timing diagrams, a multimeter, and the recurring discovery that ground is not optional.
  • SBC bring-up (Raspberry Pi, Pico) often GPIO, buses, power sequencing, thermals — everything a datasheet promises and hardware then negotiates.

Web, secondary & tooling

Web & secondary

used with intent, not by default

  • TypeScript often Frontends that stay small. Types as documentation that the compiler actually reads.
  • JavaScript often Both sides of it: modern ESM where possible, and whatever legacy thing needs patching today.
  • HTML & SCSS often Semantic markup, custom properties, no framework — this site is the reference implementation.
  • Bash daily The duct tape. Almost every build, deploy and recovery story starts as a shell script.
  • SQL often Schemas designed before the first insert. Migrations are planned, not discovered.
  • Swift occasional Apple platforms, when a project insists on them. Pleasant language, opinionated hallway.
  • Kotlin occasional Android when it is the right target, and a genuinely nice language to think in.
  • Flutter occasional Cross-platform interfaces where that trade-off makes sense — prototypes, mostly.

Environment & tooling

the machine that runs all of it

  • Linux · CachyOS / Arch daily Daily driver. Rolling release, pacman and the AUR, and full control of the boot chain when it matters.
  • Hyprland & KDE daily Tiling for work; KDE when a graphical session should behave like a desktop instead of a puzzle.
  • git daily Rebased, squashed, bisected. History is a tool, not an archive.
  • GCC · Clang · cross-toolchains daily Including the cross-builds a kernel needs before it is allowed anywhere near real hardware.
  • CMake · Meson · Make daily Build systems that produce exactly what the build file says, which is more than some can claim.
  • gdb · perf · strace often Debugging starts with measurement, and ends with printf far more often than anyone admits.
  • QEMU often Where kernel work happens before it has to be brave enough to run on real hardware.
  • systemd often Units, timers, journal. Deployments that survive a reboot without a babysitter.

Caveats

The part most lists leave out.

  • Anything missing here is either forgotten or genuinely absent. Unlikely to be the first.
  • The levels are conservative on purpose: "often" means I would ship it tomorrow without asking anyone.
  • A framework is not a language. Used is not the same as authored, and this page does not pretend otherwise.
  • Everything here is boring by choice. Boring tools are the ones that still work at three in the morning.
